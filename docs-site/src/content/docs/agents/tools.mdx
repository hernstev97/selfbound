These are all the tools Selfbound's MCP server offers. The page is generated from the server's tool list, so
the descriptions below are the same ones your agent sees. Tools marked **read** never change anything; tools
marked **write** do.

## How agents refer to things

- **Issues** by identifier, such as `ACME-42`. Spelling is forgiving (`acme42` and `acme 42` work), and
  old identifiers of issues that moved to another team still resolve.
- **Teams** by key, such as `ACME`.
- **Labels, projects and statuses** by name, case-insensitive. Each team has its own statuses; agents
  can also use a status key (`triage`, `backlog`, `todo`, `in_progress`, `in_review`, `done`, `canceled`,
  `duplicate`), which maps to the team's matching status.
- **Priorities** as a word (`urgent`, `high`, `medium`, `low`, `none`) or a number from 0 to 4.
- **Models** as `{ provider, modelId, effort?, speed? }` with values from `list_models`. Issues report their own
  `model` and the `effectiveModel` that applies (own, parent's or team default, with `source`); the `model` filter
  of `list_issues` and `search_issues` takes `"provider/modelId"`, a model ID, a provider or `"none"`.

Errors such as an unknown label, a status the workflow doesn't allow or a full hard
[priority limit](/concepts/issues/#priority) come back as a readable message, so the agent can correct itself and
try again.
