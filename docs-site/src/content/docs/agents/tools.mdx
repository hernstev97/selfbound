These are all the tools Selfbound's MCP server offers. The page is generated from the server's tool list, so
the descriptions below are the same ones your agent sees. Tools marked **read** never change anything; tools
marked **write** do.

## How agents refer to things

- **Issues** by identifier, such as `ACME-42`. Spelling is forgiving (`acme42` and `acme 42` work), and
  old identifiers still resolve: those of issues that moved to another team, and those with a team's old key
  after a rename.
- **Teams** by key, such as `ACME`. After a rename the old key works too; `list_teams` shows it as `previousKeys`.
- **Labels, projects and statuses** by name, case-insensitive. Each team has its own statuses; agents
  can also use a status key (`triage`, `backlog`, `todo`, `in_progress`, `in_review`, `done`, `canceled`,
  `duplicate`), which maps to the team's matching status.
- **Priorities** as a word (`urgent`, `high`, `medium`, `low`, `none`) or a number from 0 to 4.
- **Models** as `{ provider, modelId, effort?, speed? }` with values from `list_models`. Issues report their own
  `model` and the `effectiveModel` that applies (own, parent's or team default, with `source`); the `model` filter
  of `list_issues` and `search_issues` takes `"provider/modelId"`, a model ID, a provider or `"none"`.

Errors such as an unknown label, a status the workflow doesn't allow or a full hard
[priority limit](/concepts/issues/#priority) come back as a readable message, so the agent can correct itself and
try again.

## Relations

Agents link issues the way you do in the app: **related**, **blocks**, **blocked by** and **duplicate of**. The
types are seen from the issue named first and use the same words as the `relations` of `get_issue` (`related`,
`blocks`, `blocked_by`, `duplicate_of`, `duplicated_by`), so an agent can pass an entry it read straight to
`remove_relations`. A relation that already exists is not added twice, an issue cannot relate to itself, and a
relation the other way round (B blocks A when A should block B) is refused until the old one is removed. Each
change appears in the history of both issues and in your inbox.

The tools change only relations. **Mark as duplicate …** in the app also sets the status to Duplicate; an agent
does that in a second step with `set_status` and the status `duplicate`.

## Images

Screenshots go into descriptions and comments as Markdown. The agent uploads the image first and pastes the
returned line (`![name](url)`) into `add_comment`, `update_issue` or `create_issues`. The images stay private in
Selfbound, like those uploaded in the app: the URL holds a secret token. PNG, JPEG, WebP and GIF are accepted, at
most 5 MB, checked by their content. Agents should compress screenshots first (WebP or JPEG, ideally under 300 KB)
because storage and bandwidth cost money. An image that appears in no text within 7 days is deleted.

## Roadmap, projects and labels

A team's roadmap shows its projects as stages and the labels of one label group as categories (see
[Roadmap and progress](/using/roadmap/)). Agents can set it up: create the projects in order with a goal, a
"ready when" and a rough period (`2027-Q1` or `2027-03`), create the category labels in an exclusive group,
assign issues with `update_issue` (`project`, `labels`), and mark the ones players may see as `public` with a
`publicTitle`, a `publicSummary` of two or three sentences and a `publicImage` from `upload_image`. Only public
issues appear in the image export, and only with those three fields.
