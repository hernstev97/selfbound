Selfbound is a fast, keyboard-first issue tracker for solo developers and their AI agents. You run your own
copy of it: it is open source (AGPL-3.0), self-hosted, and keeps issues, sprints, projects and knowledge
pages for one person in one place.

<Screenshot name="list" alt="The Selfbound issue list with teams in the sidebar and issues grouped by status" />

## Who it is for

- **You build software mostly on your own** and want a tracker that keeps up with your keyboard instead
  of slowing you down.
- **You work with AI agents** such as Claude Code, Codex, claude.ai or ChatGPT, and want them to read
  and write issues directly. Each agent gets its own key, and the history shows which agent changed what.
- **You are fine with running it yourself.** Selfbound needs a Convex account for the backend and a Clerk
  account for sign-in. There is no hosted version.

Every instance belongs to one owner. The backend lets in only the sign-in accounts listed in
`SELFBOUND_OWNER_IDS`. You can list more than one account there, for example two ways you sign in, but they
all act as the same owner: Selfbound does not tell people apart. Small teams are not the target today.

## What Selfbound is not

- **Not a hosted service.** There is no Selfbound cloud to sign up for. You deploy your own instance (see
  [Self-hosting](/start/self-hosting/)).
- **Not a tool for collaboration between people.** Issues have no assignees, and there are no user
  accounts, roles or permissions.
- **Not a replacement for Jira or Linear in an organization.** It covers what one developer and their
  agents need, and stays small for that reason.
- **Not a native mobile app.** Selfbound is a web app with a phone layout. You can install it on your phone
  or desktop and get push notifications.

## Speed

The app keeps all data of your workspace in memory and renders from there, so most actions do not wait
for the network. The budget is 100 ms at the 95th percentile for every interaction with 10,000 issues,
measured on an idle machine. CI runs a quick performance check on every change with a looser limit
(250 ms), which catches larger slowdowns.

## What you can do with it

- **[Teams](/concepts/teams/):** separate areas of work, each with its own key (`ACME` in `ACME-42`), statuses and
  optional knowledge area.
- **[Issues](/concepts/issues/):** priorities, labels, estimates, due dates, sub-issues and relations
  such as "blocks" or "duplicate of".
- **[Workflow](/concepts/workflow/):** statuses per team, from Triage and Backlog to Done.
- **[Triage and inbox](/concepts/triage-and-inbox/):** sort new issues, and see what your agents created.
- **[Sprints](/concepts/sprints/):** one sprint that spans all teams, with planning and closing.
- **[Projects](/concepts/projects/)** and **[labels](/concepts/labels/)** to group work across views.
- **[Knowledge](/concepts/knowledge/):** pages per team, linked with issues.
- **[Agents](/agents/overview/):** an MCP endpoint for Claude Code, Codex and other clients, and OAuth
  connectors for claude.ai and ChatGPT.
- **[GitHub](/integrations/github/):** pull requests appear on their issue, live through webhooks, and
  merging can complete the issue.
- **[Keyboard](/reference/keyboard-shortcuts/):** a command menu (<Kbd keys="mod+k" />), search
  (<Kbd keys="/" />) and shortcuts for nearly everything.

It also has list and board views, an installable app with push notifications, themes (including VS Code
themes), an English and a German interface, and an [import from Linear](/integrations/import-linear/).

## How it is built

Selfbound is a Svelte single-page app on a [Convex](https://convex.dev) backend, with sign-in through
[Clerk](https://clerk.com). For you as a self-hoster this means two accounts: one at Convex (database and
backend functions) and one at Clerk (sign-in). The Convex free plan is enough for one person. The web
app itself is a set of static files that any static host can serve.
